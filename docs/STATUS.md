# Doc Gardener — статус относительно брифа

Состояние на 2026-10-27. Как проверялось: 58 автотестов (`python3 -m unittest discover -s tests`) и прогон на трёх реальных репозиториях: монорепо с агентскими скиллами (~170 страниц), backend-сервис (~160), Obsidian-подобное хранилище заметок (~900). Полный `check --all` занимает 0.5–1.5 с. На копии одного репозитория проведён перенос каталога `docs/`: 0 сломанных ссылок, число предупреждений до и после совпало.

Легенда: **готово** — реализовано и покрыто тестами; **частично** — реализовано с известными ограничениями; **инструкция** — есть только как процедура для LLM; **нет** — отсутствует.

## Сценарий «построй здесь базу знаний» (BOOTSTRAP)

| Шаг | Чем обеспечен | Статус |
| --- | --- | --- |
| Сканирование структуры | `scan`: агентские инструкции, рендереры, пакеты, области документации, конвенции ссылок, frontmatter и имён, язык, сгенерированные и крупные страницы, текущее здоровье | готово |
| Вопросы пользователю | `scan` формирует открытые вопросы с вариантами по умолчанию; агент задаёт их одним сообщением (`skills/doc-gardener/references/ONBOARDING.md` §2) | готово (вопросы) + инструкция (диалог) |
| Конфиг | `init` строит черновик `.doc-gardener.json` (exclude, entrypoints, allow_orphans, mappings), не перезаписывает существующий | готово |
| Предложение структуры | Шаблон предложения: дерево, карта страниц, навигация, батчи, что не меняется, риски (`ONBOARDING.md` §3); dry-run `move` проверяет план | инструкция + готово (проверка плана) |
| Согласование | Gate: структурные изменения только после явного одобрения (инвариант 8 в SKILL.md) | инструкция |
| Перенос | `move --apply`: `git mv`, переписывание inline-ссылок, reference-определений, wiki-ссылок и упоминаний путей в backticks, перенос ассетов, отчёт о внешних упоминаниях (nav рендерера, конфиги, комментарии в коде), повторная проверка | готово |
| Переработка содержимого | Батчи: индексы → консолидация → разбиение → связи → пробелы; после каждого `check --all` и коммит | инструкция |
| Активация | `AGENTS_SNIPPET.md`, вендоринг скрипта, CI, Stop hook | готово (примеры; hook проверен вручную) |

## Возможности из брифа

| Возможность | Статус | Комментарий |
| --- | --- | --- |
| Broken links / anchors | готово | ATX и setext, GitHub-slug (snake_case и inline-код в заголовке сохраняются), `{#id}`, HTML `id`/`name`, ссылки без расширения |
| Wiki-links | готово | `|label`, `#heading` (по тексту заголовка), `#^block`, неоднозначность |
| Backlinks, orphans, reachability | готово | CHANGELOG, LICENSE, SECURITY, `.github/**` не считаются orphan |
| Точные дубли, одинаковые секции, почти-дубли | готово | почти-дубли считаются по 5-словным шинглам; это сигнал для триажа, не вердикт |
| Duplicate IDs | готово | при `--policy` |
| Index validation | готово | `index --check`: устаревший managed-блок или страницы, не попавшие в ручной индекс |
| Git impact | готово | без конфига: документы, которые ссылаются на изменённый код или упоминают его, в том числе на удалённый файл и старый путь переименованного (`git diff --no-renames`, ключ отчёта `missing_code_refs`); плюс опциональные `mappings` |
| Инкрементальная проверка | готово | `check --changed <rev>` |
| Устаревшие ссылки на код | готово | `check --code-refs`, только предупреждения |
| Graph export | готово | json / dot |
| DISCOVER: поиск нужного | частично | `route`: лексический ранжир страниц и секций с диапазонами строк; без эмбеддингов, синонимы — переформулировкой запроса |
| Code → docs: смысловая проверка | инструкция | скрипт сужает круг документов; правильность утверждений проверяет агент |
| Поиск недостающих смысловых связей | инструкция | скрипт не придумывает связи |
| Независимость от проекта | готово | сканируется весь Markdown, известный git; нет обязательных папок, frontmatter и стиля ссылок |
| Hooks | готово (пример) | Claude Code Stop hook в `skills/doc-gardener/references/HOOKS.md`; у Codex и Cursor остаются инструкция и CI |
| Периодический аудит | нет | нужен планировщик агента или CI cron (`check --all --json`) |
| Гарантия вызова скилла | нет | невозможно на уровне скилла; снижается правилом в AGENTS.md, хуком и CI |

## Исправления 0.3.1

Найдены code review на вендоренной копии, каждое воспроизведено тестом до исправления:

- `move`: существующий путь назначения отклоняется, даже если он сам источник в том же плане. Переносы применяются по одному, поэтому `a.md -> b.md, b.md -> c.md` раньше затирал `b.md` и сообщал об успехе.
- `check`: якоря заголовков строятся по строкам с сохранённым inline-кодом. «What `--auto-author` does» даёт GitHub-slug `what---auto-author-does`; раньше такая ссылка считалась `broken_anchor` и блокировала Stop hook.
- `impact`: упоминание несуществующего пути сохраняется в новом ключе отчёта `missing_code_refs` (`{страница: [пути-кандидаты]}`: папка страницы и каждый предок до корня). Удалённый файл маршрутизируется к документам, которые его упоминали. Предупреждения `stale_code_ref` не изменились.
- `impact` и `check --changed`: `git diff --no-renames`, поэтому переименование даёт и старый путь. Раньше документы, упоминающие старый путь, и ссылки на переименованный документ выпадали из выборки.

## Известные ограничения

- Парсер — приближение CommonMark: многострочные ссылки, ссылки внутри HTML-блоков и роутинг конкретного рендерера (например `slug` в Docusaurus) не поддерживаются.
- `stale_code_ref` срабатывает на примеры путей в инструкциях: «путь в проекте пользователя» не отличить от «пути в этом репозитории». Решение — `code_ref_ignore`.
- `route` не знает синонимов и транслитерации. Агенту стоит пробовать 2–3 формулировки.
- `move` не создаёт redirect-заглушки. Внешние ссылки (другие репозитории, закладки) он только перечисляет в follow-up.

## Что ещё не доказано

Критерии из §10 брифа (меньше прочитанных файлов и токенов, меньше пропущенных обновлений) требуют эксперимента. Протокол: 3–4 репозитория разных типов, 10 фиксированных задач на каждый, прогон без скилла и со скиллом. Метрики: прочитанные файлы, токены, время до первого релевантного файла, пропущенные обновления документации по итоговому diff.
